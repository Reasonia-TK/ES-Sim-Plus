# 130: v2 P6 — UI の作り直し (計画)

計画書: `prompts/119-v2-rebuild-plan.md` (P6: UI v2 シェル)。v1 の機能一覧 (網羅チェックリスト):
`prompts/131-ui-v1-feature-inventory.md`。

## 目的

計算側 (P0〜P5) は v2 エンジンに置き換わったが、UI は v1 (`frontend/`、約 2.2 万行、App.tsx だけで 3,900 行) の
ままで、次の問題がある:

- 設定の多く (PIC・1D・流体・TL) が元に戻せない、新規・名前を付けて保存・最近使ったファイル・未保存の確認が無い
- 同じソルバーを同時に複数回実行できず、実行ごとの結果を比較できない
- 描画が Canvas2D で毎回全三角形を塗り直す (大きな格子・AMR・GPU 計算の結果で遅い)。1D グラフに拡大・カーソルが無い
- 画面の文言・レイアウトがコードに直書き (日本語のみ)、設定欄は手書きのフォーム

v1 の全機能 (prompts/131) を失わずに、これらを解決した UI を `ui/` に新しく作る。

## 方針 (提案、要確認)

1. **新しいアプリを `ui/` に作り、v1 (`frontend/`) は動く状態で残す** (strangler)。P6 の最後に Tauri のフロントエンドを
   `ui/` に切り替える。それまで v1 の WebSocket の API も残す。
2. **画面構成** (COMSOL 風): 左にモデルツリー、中央に設定、右にグラフィックス (タブで複数のビュー)、下にメッセージ/
   進捗/ジョブ。ペインはリサイズ・折りたたみでき、配置は保存する。
3. **技術**: React 19 + TypeScript + Vite (当初は Smart App Control のため Vite 6 に固定する案だったが、SAC が
   無効になったので現行の Vite 8 にした — 下の「P6a の記録」)。
   状態は Zustand + Immer (プロジェクト全体を 1 つの文書として持ち、全ての設定を元に戻せる)。グラフは uPlot、2D 表示は
   自前の WebGL2 (文字・ハンドルなどは同じ座標系の Canvas2D を重ねる)。メニュー・ダイアログ・ツールチップは Radix UI、
   ペインは react-resizable-panels、翻訳は i18next (日本語が既定 + 英語)、テストは Vitest (+ 可能なら Playwright)。
4. **ジョブ管理**: バックエンドに `/v2/jobs` を追加 (同じソルバーの複数同時実行、実行ごとの結果の保持、停止・続き・一覧、
   イベントは 1 本の WebSocket に多重化)。既存のシミュレーションクラスの run_batch (callback / should_stop) の上に作る。
5. **フォーム**: 範囲・既定値・型はバックエンドの JSON Schema (pydantic) から、単位と「詳細設定」の印はスキーマに追記
   (`json_schema_extra`)、表示名・ヒントは翻訳ファイル。ページごとの並び・条件付き表示は UI 側の小さな定義で持つ。
   数値欄は単位付き入力 (例: `13.56 MHz`、`5 mm`) を受け付ける。
6. **CAD**: P6 では v1 と同等の作図・編集・配置ツールを新しいキャンバスへ移植し、拡張 (スナップの種類・拘束・ブーリアン・
   DXF など) は P7 で行う。

## 構成

```
ui/
├── src/
│   ├── app/        シェル (レイアウト・メニュー・コマンド・ショートカット・テーマ・ステータス)
│   ├── model/      プロジェクト文書のストア (Immer のパッチで元に戻す/やり直し)・未保存の印・選択
│   ├── schema/     /v2/schema の取得、フォームの生成 (単位・範囲・詳細設定・条件付き表示)
│   ├── tree/       モデルツリー (プロジェクトとジョブから組み立てる、右クリックメニュー・キーボード操作)
│   ├── pages/      ノードごとの設定ページ (生成したフォーム + 専用の部品: RF・CSV 波形・LXCat・頂点表など)
│   ├── graphics/   WebGL2 の 2D ビューア (メッシュ・場・粒子・重ね描き・プローブ・書き出し) と CAD ツール
│   ├── plots/      uPlot のグラフ、ヒートマップ
│   ├── jobs/       /v2/jobs のクライアント、ジョブと結果のストア
│   ├── results/    モジュールごとの結果ビュー
│   ├── io/         開く・保存 (Tauri / ブラウザ)・最近使ったファイル・自動保存
│   ├── i18n/       ja.json / en.json
│   └── util/       単位・数値の書式と解析・CSV・ハッシュ
└── tests/
```

- **プロジェクトファイル**は v1 と同じ JSON (backend の `Project`) を保つ。UI の状態 (ビュー・配色など) は任意の `ui` キーに
  入れる (backend は未知のキーを無視する)。
- **2D ビューア**: 三角形メッシュを GPU に 1 回だけ送り、フレームごとには値のバッファだけ更新する。値 → 色はシェーダ内の
  配色テクスチャ (線形/対数、範囲は uniform)。節点量は滑らかに、要素量は三角形ごとに塗る。等値線はシェーダ (節点量の
  補間値から) または CPU の marching triangles、矢印・粒子はインスタンス描画。プローブ・ホバーは格子のバケットで O(1)。
- **ジョブ API** (案): `POST /v2/jobs` {kind, project, options} → id、`GET /v2/jobs`、`POST /v2/jobs/{id}/stop`・
  `/continue`、`DELETE /v2/jobs/{id}`、`GET /v2/jobs/{id}/result`、`WS /v2/events` (started / frame / progress / done /
  error を job id 付きで)。同時実行数は種類ごとと全体の上限で待ち行列に入れる。

## P6a の記録 (2026-09-29)

- **技術の版**: Smart App Control が無効になった (ユーザー、2026-09-29) ので、古い版への固定をやめて現行の安定版で始めた:
  React 19.3・Vite 8.3 (rolldown)・@vitejs/plugin-react 6・Vitest 5・TypeScript 5.9・Zustand 5・Immer 11・
  i18next 26 / react-i18next 17・radix-ui 1.6・react-resizable-panels 4。開発サーバーは 1421 (v1 の 1420 と並べて使える)。
- **文書** (`model/documentStore.ts`): プロジェクト全体を 1 つの文書として持ち、編集は Immer のパッチで履歴 (200 件) に
  積む。全ての設定が元に戻せる。未保存かどうかは状態 ID で判定 (元に戻して保存時と同じ状態になれば未保存の印も消える)。
  ファイルを開くと新しい文書になる (v1 は読込を元に戻せたが、代わりに開く前に未保存の確認をする)。
- **ファイル** (`io/`): Tauri はネイティブのダイアログとパス、ブラウザは File System Access API のファイルハンドルを
  IndexedDB に保存して上書き保存・最近使ったファイル (10 件) を実現、API の無いブラウザはダウンロード。サンプルは
  examples/*.json をビルド時に取り込む。自動保存は未保存の変更を 30 秒ごと (とページを閉じるとき) に localStorage へ
  写し、次の起動時に復元するか尋ねる。
- **ツリー** (`tree/`): 検索、折りたたみ (境界条件は辺が 8 本を超えると最初は閉じる)、ARIA の tree/treeitem、キーボード
  (↑↓←→ Home End F2 Delete)、右クリック (領域の追加・名前変更・複製・削除)、その場で名前変更 (空・重複を拒否)。
- **設定** (`pages/`): P6a はプロジェクト・ドメイン (座標系、軸対称にすると対称軸の辺の境界条件を外す)・領域 (ID・種類・
  値・円の中心と半径) を編集でき、ほかは内容の表示だけ。数値欄は v1 と同じ確定の流儀 (Enter / フォーカスが外れたら
  確定、Esc・不正な値は戻す) で、確定できない理由を欄の下に出す。
- **グラフィックス**: P6a は Canvas2D のジオメトリ表示 (境界条件の色分け・対称軸・領域・クリックで選択)。P6c で WebGL に。
- **バックエンド**: `GET /v2/schema` (Project の JSON Schema、286 項目・39 型)。接続は 5 秒ごとに /health を見て、
  つながったらスキーマを取り直す。ポートの保存先は v1 と同じ (Tauri は AppConfig/backend-port.txt、ブラウザは localStorage)。
- **検証**: Vitest 31 件 (文書の履歴と未保存の判定・プロジェクトの読込と全サンプル・ツリーの組み立てと検索・領域の操作・
  数値の表示と解析・接続・設定欄とツリーの操作・アプリ全体の描画)、pytest (`tests/test_v2_ui_api.py`)、ブラウザで
  編集 → 元に戻す/やり直し・入力エラー・F2 の名前変更・削除の確認・メニュー (サンプル・未保存の確認)・テーマと言語の切替・
  バージョン情報・自動保存からの復元を確認。ネイティブのファイルダイアログ (保存・開く) は自動操作できないので未確認。

## P6b の記録 (2026-09-30)

- **スキーマの追記** (backend `schema.py` の `ui()`): 全ての数値の項目に単位 (`x-unit`、SI で保存する値の単位、
  無次元は "1")、幾何の長さ・座標に `x-geom` (表示単位 mm/µm で入出力)、乱数シード・スレッド数・メッシュの粗さ
  などに `x-advanced` (詳細設定)。`tests/test_v2_ui_api.py` が「数値なのに単位が無い項目」を検出する。
  UI には同じスキーマを同梱 (`ui/src/schema/project.schema.json`、`python -m es_sim.ui_schema` で書き出し、
  古いとテストが失敗する) し、未接続でもフォームを出せる。`/health` にサーバーの instance を加え、再起動したら
  スキーマを取り直す (版が同じでも schema.py が変わっていることがあるため)。
- **フォームの生成** (`ui/src/forms`、`ui/src/schema`): path を渡すだけで、種類 (数値・整数・真偽・選択肢・文字列・
  座標)・単位・範囲 (境界を含む/含まない)・既定値・null (自動) の可否・詳細設定の印をスキーマから決めた入力欄になる
  (`SchemaField`)。表示名・選択肢・ヒントは翻訳ファイル (`fields/enums/hints.<型名>.<項目>`、無ければ `_common`)。
  置き忘れた項目も並べる `AutoFields`、有効/無効を切り替えて無効にしても値を覚えている `OptionalBlock` (v1 の [R])。
- **単位付きの入力**: `13.56 MHz`・`0.5 ns`・`10 mTorr`・`5 keV`・`1e10 cm^-3`・`0.5 cm` のように単位を書ける
  (SI 接頭辞と別名)。単位を省くと表示単位。違う種類の単位・範囲外はその場で理由を出して確定しない。軸対称では
  A/m を A と読み替える (v1 と同じ)。
- **ページ**: プロジェクト・ドメイン (多角形は頂点の表)・領域 (導体の RF・CSV 波形・電圧プレビュー・γ、誘電体、
  電荷、円/多角形の頂点、他の領域との結合、局所メッシュ幅)・境界条件 (一覧と辺ごと: Neumann/Dirichlet/対称/周期、
  周期は向かいの辺と自動で対、共有する条件の注意)・磁場・メッシュ (方式ごとの説明、AMR: 最大レベル・緩衝セル・
  適応細分化・PIC/DSMC の再格子化・細分化矩形、辺の局所メッシュ幅)・全スタディ (静電場・粒子軌道・PIC・PIC 1D・
  流体 1D/2D・DSMC・VHF 定在波・パラメータスイープ)。
- **部品**: RF 成分 (v1 の既定値)、CSV 波形 (1 つ / 1D 電極は複数)、電圧プレビュー (uPlot)、LXCat の取り込み
  (/lxcat/parse、警告の表示)、頂点の表、領域の結合 (polygon-clipping、v1 と同じ規則)、一覧の編集 (コレクタ 8・
  EEDF 領域 4・シース評価線 4・AMR の矩形・辺のメッシュ幅・DSMC の境界・1D の EEDF 区間)、1D の電極 (FN)、
  FN 放出 (放出面の選択)、Boltzmann 係数 (表の情報・断面積との鮮度: Python の json.dumps + sha256 とビット一致)、
  PIC 1D のプリセット (/pic1d/presets)、流体への取り込み (PIC 1D → 流体 1D、流体 1D → 流体 2D)、実行設定の目安

- **v1 からの意図的な変更**: PIC の注入のエミッタは粒子軌道のエミッタに暗黙に合わせず、注入自身の設定にした

## P6c の記録 (2026-09-30)

- **ビューア** (`ui/src/graphics`): 3 枚の層を重ねる。下は Canvas2D (背景・ドメイン・グリッド)、中は WebGL2
  (場・メッシュ・等値線・粒子・線分)、上は Canvas2D (ジオメトリ・境界条件の色分け・対称軸・領域・配置物・選択と
  ハンドル・作図中の線・計測・プローブ・カラーバー・ルーラー)。描き直しは React の反映ごと (イベントごとにまとまる)。
  requestAnimationFrame と ResizeObserver はウィンドウが隠れていると止まるので、描く前に大きさを測り直す。
- **WebGL2** (`gl/renderer.ts`・`gl/shaders.ts`): 三角形ごとに節点番号を 3 個並べるだけの頂点バッファで、座標・値・領域は
  float テクスチャから texelFetch で読む (値だけ差し替えれば描ける = P6e の実行中の表示もこのまま)。値 → 色は配色の
  テクスチャ (256 段、v1 と同じ 7 種) で、線形/対数・範囲は uniform。節点量は三角形の中で滑らかに (v1 は三角形ごとに
  3 節点の平均で 1 色)、三角形の量は一色。メッシュの線は重心座標と fwidth で同じ描画の中に描く (追加の頂点なし)。
  NaN・無限大は欠けた値として塗らない。線分 (等値線・軌道・シース端) は画面で幅のある四角形のインスタンス描画、
  粒子は丸い点。座標はドメインの中心を引いて float32 に。GPU の資源はデータのオブジェクトごとに作って使い回し、
  使わなくなったら消す。文脈を失ったら作り直す。24.5 万三角形・13 万節点で描き直し 11 ms。
- **カメラ** (`camera.ts`): 全体表示 (80%、ルーラーの分を除く)・ホイールでカーソル中心の拡大 (×1.15/ノッチ、範囲の
  制限あり)・中ボタンか Space + ドラッグで移動・F/Home で全体表示。グリッドは 20 px 以上の 10 の累乗 (v1 の 1 mm の
  下限を外した)、スナップはその 1/10。スナップした座標・移動量は 1 pm で丸めて保存 (0.1 + 0.2 の端数を残さない)。
- **プローブ・ホバー** (`meshIndex.ts`): 三角形を格子のバケツに入れて点の所属を O(1) で (v1 は全三角形を総当たり)。
  節点量は重心座標で補間、三角形の量はその値。ホバーでカーソルの下の値を下に出す。プローブの値は描くたびに今の場から
  読む (P6e のアニメーションに追従)。
- **表示の設定**: 量 (V・|E|)、配色 7 種、範囲 (最小・最大を別々に、空欄 = 自動)、対数、メッシュの線、等電位線
  (15 本、v1 と同じ marching triangles)、電場の向きの矢印 (画面の格子で最大 ~600 本、拡大しても密度が一定)、
  配置物ごとの表示、AMR の細分化の矩形、グリッド・ルーラー (文字 3 段)・凡例。配色と表示の切り替えは使う人の好み
  として localStorage に残す (文書の `ui` キーには入れない、結果付き保存は P6e)。
- **CAD** (v1 と同じ規則): 選択 (面積の小さい領域を優先、輪郭から 6 px)・移動 (半透明のプレビュー)・頂点のドラッグ・
