# 84: 粒子のセル順ソート (空間局所性の改善、高速化③)

## 背景

融合済みの押し出し+walk がメモリ帯域律速 (ベンチで~36%)。粒子は生成順のまま
なので、隣り合う粒子が触るメッシュデータ (節点値・要素係数) がバラバラで
キャッシュ効率が悪い。**定期的に粒子配列を所属要素 (elem) 順に並べ替える**ことで
gather/deposit/walk の局所性を上げる。古典的な PIC 最適化で、粒子数が大きいほど効く。

## 仕様

- 対象: PIC の全種 (electron / ion / immobile は不要 — 動かない種はスキップ)。
  DSMC も同じ構造なら同様に入れて良い (効果測定して割に合う場合のみ)。
- 間隔: `SORT_EVERY = 50` ステップごと (モジュール定数、コメントに根拠:
  ソートは O(N log N) だが50ステップ償却でほぼゼロ。粒子は1ステップに
  セル数個分しか動かないので50ステップ程度は順序がほぼ保たれる)。
- 実装: `order = np.argsort(sp.elem, kind="stable")` で置換配列を作り、
  種の**全粒子配列** (x, v, w, elem、その他 species が持つ per-particle 配列を
  漏れなく) を order で並べ替える。stable にする理由 (同一セル内の相対順を保ち、
  乱数消費順の変化を最小にする) をコメントに書く。
  ユーザーの perf コミットで導入されたバッファ再利用と衝突しないよう、
  再利用バッファの扱い (並べ替え後に無効化 or 同時に並べ替え) を現行実装を
  読んで正しく選ぶ。
- 適用タイミング: ステップ末尾 (診断記録の後) が安全。イオンサブサイクルの
  キャッシュ (_f_ion_cache 等) や immobile のデポジットキャッシュがあるなら
  並べ替えで無効化が必要 — 現行の注入/電離時の無効化処理と同じ扱いにする。
- **結果への影響**: 粒子順序が変わるため、乱数を粒子順に消費する処理
  (MCC等) の対応が変わり、従来実行とはビット単位では一致しなくなる
  (統計的には同等)。これは許容する (コメントと最終報告に明記)。
  ただし「同一シードなら再実行で同じ結果」の決定性は保たれること。
  threads=1 vs N の一致テスト等、既存の決定性テストが通ることを確認。

## 検証

1. `python -m pytest tests/ -q` 全件パス (現在 205)。物理回帰が出た場合は
   順序変更に敏感な (ビット一致前提の) テストかを見極めて対処。
2. ソートの単体テスト: ソート後に全配列の対応 (x[i] と elem[i] の組) が
   保たれていること、elem が非減少になっていること。
3. ベンチ: `python backend/benchmarks/pic_bench.py` を既定 (2万粒子) と
   `--n-macro 200000` 相当の大粒子数 (引数が無ければ一時的に変数を変えた
   ワンショット実行で良い) の両方で前後比較。**効果は大粒子数側で評価**する。
   2コア環境では帯域差が出にくい可能性もある — 効果が僅少でも正直に報告
   (メニーコア・大L2の実機では効く見込みをコメントに記す)。
4. 物理不変の確認: 小ケースで sort あり/なしの診断履歴 (ke_e 等) が
   統計的に同等 (最終値が数%内) であること。
