# 136: 軸対称 PIC の軸の近くの雑音 — 半径に比例した重み (計画)

依頼 (2026-10-04): 「軸の近くの雑音の対策に進んで」 (prompts/135 の GEC の PIC の検証で見つかった問題、記録は
prompts/134 の「GEC の PIC の検証」)。

決めたこと (2026-10-04):

- 外へ出て軽くなった粒子は対の併合 (電荷を厳密に保存) で減らす (分割だけ・ロシアンルーレットではなく)。
- 軸対称の v2 PIC では既定でオン (設定で一様の重みに戻せる)。
- 対象は v2 PIC (直交格子、一様格子・AMR) だけ。v1 PIC は今のまま。
  → 2026-10-04 に「v1 PIC にも半径に比例した重みを入れて」で v1 PIC にも入れた (RW-c)。

## 問題

- 軸対称の v2 GPU PIC はマクロ粒子の重みが一定 (`gpic/simulation.py` の `_load_initial_plasma` の w0、電離・
  二次電子の粒子は親の重みを引き継ぐ)。粒子は体積に一様に置くので、セルあたりの粒子数は r に比例し、軸の近くには
  ほとんどいない (GEC、0.25 mm・400 万粒子で r = 1 mm のデバイ長のリングに約 2 個)。
- 粒子 1 個の電荷がほぼ点電荷として効き (リングの線電荷 w·e/(2πr) が軸へ向かって大きくなる)、統計の雑音で電子が
  加熱される (雑音による加熱 ∝ 重み/r)。GEC (13.33 Pa) では軸の近くの電離が r 15〜20 mm の 2〜7 倍になり、密度の
  山が育つ (0.5 mm・100 万粒子では 125 周期で最大 7.9×10¹⁵ m⁻³)。400 万粒子でも軸の近くの密度は 1.2〜1.3 倍。
- 自己バイアスはほとんど変わらない (軸の近くは電極の面積のごく一部)。

## 文献 (2026-10-04 に確認)

- Hara, Robertson, Kenney, Rauf, "Effects of macroparticle weighting in axisymmetric particle-in-cell Monte Carlo
  collision simulations" (PSST、2022 年 10 月投稿の原稿、OSTI 2421616): 同じ GEC セル (5 nF、25〜100 mTorr、
  100 V) で同じ現象。軸の近くの重みが大きいと中心の電子密度が約 2 割・電子エネルギーが約 2 割過大になり、粒子を
  増やすか軸の近くの重みを小さくすると収束する。自己バイアスは −82.5 V で重みによらない。重みは r の 1 次式
  w(r)/W0 = (1 − α) r/R + α (α = 0.025)。重みが 2 w(r) を越えたら同じ速度のまま等分に分割 (運動量・エネルギーを
  保存)。外へ出た粒子は併合しない。Rauf (PSST 29, 095019, 2020) も同様の重み付けで、100 mTorr では密度が中心
  でなく周辺で高い (Langmuir プローブの実測と合う)。
- Teunissen & Ebert, J. Comput. Phys. 259, 318 (2014): 近い粒子の対の併合。性質を重みに比例した確率で一方から
  選ぶ方式は、電荷を厳密に、運動量・エネルギーを期待値で保存し、速度分布を歪めない。
- Lehe, Formenti, Angus, Vay, arXiv:2608.23894 (2026): 重みの違うマクロ粒子は PIC の数値的な衝突で違う温度に
  落ち着く (軽い粒子が熱くなる)。同じ場所の粒子の重みの比を小さく保つのがよい。CCP では中性粒子との衝突 (MCC、
  重みによらない) が数値的な衝突よりずっと速く熱化するので影響は小さいはず。

Hara らは併合をしないので、軽い粒子が電離で軽い粒子を生み、粒子数は時間とともに増える。ここでは併合も入れて
粒子数を目標の分布に保つ。

## 設計 (案)

### 目標の重み

- w_t(r) = c (r + r0)、r0 = 基本格子の 1 セル。セルあたりの粒子数が r によらずほぼ一定になる (軸のセルは半分)。
  リングの線電荷 w·e/(2πr) は r ≳ r0 で一定 (平面の 2D と同じ雑音の大きさ)。
- c は初めの装荷で決める: r は一様 (体積に一様ではなく) に、z は一様に引き、r < r0 は r/(r + r0) の確率で採る
  (密度を一様に保つ)、気体の外は捨てる。全電荷が n·V_gas になるよう c を決める。電子とイオンは同じ位置・重み
  (quiet start のまま)。

### 粒子の数の調整 (毎ステップ、種ごと、CUDA Graph の中、MCC のあと)

- 分割: w > 2 w_t(r) なら m = round(w/w_t) 個 (上限 8) に等分。位置・速度は同じ (電荷・運動量・エネルギーを厳密に
  保存)。複製どうしは MCC の乱数 (粒子番号ごと) で別れる (13 Pa の電子で約 20 ステップ)。追加は電離と同じ
  atomicAdd と容量の仕組み (軟らかい容量・停止とやり直し)。
- 併合: w < w_t/2 の粒子は、同じセルの同じ種の軽い粒子と対にする (セルごとの空き枠を atomicCAS で取り合い、
  待っている粒子がいれば組む)。重み w_a + w_b の 1 個にし、位置・速度は重みに比例した確率で一方を選ぶ (電荷は
  厳密、運動量・エネルギーは期待値で保存、分布は歪めない)。相手がいなければ次のステップに持ち越す。もう一方は
  w = 0 (次の圧縮で詰める)。
- 数え方: 分割・併合の累計をカウンタに持つ。履歴の生きている粒子数は壁の吸収と同じように併合を差し引く。容量の
  先回りの速さに分割の数を足す。履歴に "merged"・"split" (累計)。
- ステップの処理の順と同じく、停止中・イオンのサブサイクルで押さないステップは何もしない。

### 設定・範囲

- `pic.radial_weighting` (軸対称の v2 PIC、既定 true)。false なら今までどおり一様の重み (比べるとき、テストで粒子を
  手で置くとき)。UI の PIC の設定に出す (軸対称のときだけ)。
- v2 GPU PIC (一様格子・AMR)。v1 PIC (CPU) は対象外 (重みの配列と Vranic の併合は既にあるので、必要なら後で)。

## 確かめること

1. 装荷: 一様プラズマの密度が軸の近くまで一様 (統計の範囲)、セルあたりの粒子数が r によらない。
2. 分割・併合: 種ごとの Σw が丸め誤差で一定 (損失の無い箱)、複製の速度が親と同じ、運動量・エネルギーが統計の
   範囲で保存、w/w_t がほぼ [1/2, 2] に収まり、粒子数が増え続けない。阻止コンデンサの電荷の保存 (軸対称) が
   丸め誤差。
3. 雑音による加熱: 熱的なプラズマ (軸対称、損失なし) で、軸の近くの電子温度の上がり方が一様の重みより十分小さい。
4. GEC (0.5 mm、100 万・400 万粒子、100 周期): 軸の近くの電離の比 (r 0〜1 mm ÷ 15〜20 mm) と密度の比が 1 に
   近づく。粒子数の推移、1 ステップの時間 (目安 +5% 以内)。
5. GEC の保存された結果を作り直す (約 1.5 時間)。密度が周辺で高くなるか (Rauf・Hara) を見る。prompts/134・135・
   README を直す。

## RW-a の記録 (2026-10-04)

実装:

- `kernels/pic.cu`: `pop_control` (種ごと、MCC のあと、CUDA Graph の中)。分割は w > 2 w_t で m = round(w/w_t) 個
  (上限 8)、同じ位置・速度で、親が残りの重みを持つ (浮動小数点でも和が変わらない)。併合は w < w_t/2 の粒子が
  セルごとの枠 (毎ステップ -1 に戻す) を atomicCAS で取り合い、待っている粒子がいれば組んで、重みに比例した
  確率で一方を残す。カウンタ (分割の複製・併合の累計、圧縮のときの併合の基準)。履歴の生きている粒子数は併合も
  差し引き、列 `merged`・`split` (累計) を足した。
- `gpic/simulation.py`: 目標の重み c (r + r0) (r0 = 基本格子の 1 セル、`RW_R0_CELLS`)、装荷 ((r, z) を一様に引いて

  一様な密度でも軸の上だけ 4/3 倍に見えていた (重み 1 − r/h の堆積が軸のセルの体積 π h²/4 より広く集めるため。
  Poisson の右辺の電荷は正しく、表示だけの問題)。
- スキーマ `pic.radial_weighting` (既定 true、詳細設定) と UI の同梱スキーマ、結果の束の診断の列に `split`。
- UI: PIC の設定の「実行設定」に「半径に比例した重み (軸対称)」(軸対称のときだけ、詳細設定)。数値サマリの診断に
  「分割で増やした粒子数 (累計)」(併合は今までの「マージで減らした粒子数」)。設定の欄のラベルのテストが全ての項目に

## RW-c の記録 (v1 PIC、2026-10-04)

依頼: 「v1 PIC にも半径に比例した重みを入れて」。

実装 (`es_sim/pic.py`):

- 目標の重み c (r + r0)、r0 = mesh.size (`RW_R0_SIZES`)。装荷は要素を面積比例で選んで要素内は一様に引いた候補を
  r/(r + r0) の確率で採り (要素内の r 依存も厳密)、全電荷から c を決める。
- 毎ステップ、MCC・注入・FN のあと (イオンは押したステップだけ) に分割と併合。分割は同じ位置・速度・要素の複製を
  電離と同じ追記 (`_append_species_buffered`) で足す。併合は軽い粒子を要素の番号で並べて同じ要素の隣どうしを組み、
  位置を重み付き平均 (同じ要素の中なので P1 の電荷堆積が厳密に変わらない)、速度を重みに比例した確率で一方のものに
  する。消える粒子は末尾の粒子をその位置へ移して詰める (O(消す数))。分割も併合も堆積を変えないので場は乱れない。
- 粒子マージ (`pic.merge`、Vranic) とは重みの調整が重なるので、merge があると使わない (警告)。
- 履歴の `merged` に併合の数を足し、`split` を新しく。表示の密度は前から形状関数の体積で割っているので、軸の上の
  4/3 倍の問題は無い。
- スキーマ・UI の説明から「v2 のみ」を外した。README・SPEC。

確かめたこと:

- テスト `tests/test_pic_radial_weighting.py` (5 件): 装荷と軸までの一様な密度、分割・併合で P1 の電荷堆積が
  相対 1e-12 で変わらないこと、損失の無い箱の重みの保存と粒子数、merge があると使わないこと、軸の近くの電位の
  揺らぎ (一様の重み 2.26 V・r 10〜20 mm 0.41 V → 半径に比例 1.24 V・0.385 V)。既存の v1 の軸対称の阻止
  コンデンサの電荷の保存のテストも、分割 1 万・併合 1 万の下で相対 1.5×10⁻¹⁵。
- 軸対称の CCP (半径 40 mm・間隔 25 mm、Ar 13.33 Pa、100 V、10 万粒子、100 周期、電極の間の中央の帯の時間平均):
