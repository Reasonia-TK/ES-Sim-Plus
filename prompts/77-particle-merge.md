# 77: 粒子マージ (高速化③、ON/OFF切替)

## 背景

大規模PICでは電離でマクロ粒子数が育ち続け、計算が際限なく遅くなる。
セル内の保存的マージでマクロ粒子数に上限を掛ける。**既定OFF、設定でON/OFF**
(ユーザー要望)。

## アルゴリズム (Vranic et al. 2015 の k→2 マージ)

種ごと・セル (メッシュ要素) ごとに、k 個 (k≥3) の粒子を2個に置き換える:

- 合計重み W = Σw、合計運動量 P = Σ w·v (3成分)、合計エネルギー E = Σ w·|v|²
  を厳密に保存する。
- 置き換え後: 2粒子とも重み W/2、速度 v± = P/W ± Δ。
  |Δ|² = E/W − |P/W|² (Cauchy-Schwarz により常に ≥ 0。数値誤差で負なら 0 に clip)。
  Δ の方向は等方ランダム単位ベクトル (シミュレーションの rng から。マージOFF時は
  乱数を一切引かないので OFF なら従来とビット単位一致)。
- 位置は重み付き平均 x̄ = Σ w·x / W に2粒子とも置く (同一セル内なので
  電荷分布の歪みはセルサイズ以下)。elem はそのセル。
- **速度空間のグルーピング**: セル内の全粒子を一括で1グループにすると
  分布関数が壊れるため、セル内でさらに速度空間で分ける:
  セル内平均速度を基準に速度3成分の符号で最大8オクタントに分割し、
  各オクタント内の粒子群 (k≥3) を1回のマージ対象とする
  (同方向・同程度の速度の粒子だけが混ざるので IEDF/IADF への歪みが小さい)。

## トリガーと目標

- `every` ステップごとにチェックし、種のマクロ粒子数 N > n_max のときだけ実行。
- 実行時は粒子数の多いセルから処理し、N が n_max の 90% 程度まで下がったら打ち切る
  (一度に削りすぎない)。1回で届かなくても次のチェックでまた削る。

## backend

### es_sim/schema.py

```py
class PicMerge(BaseModel):
    """粒子マージ設定 (prompts/77)。有効時、種ごとのマクロ粒子数が n_max を
    超えたら every ステップごとにセル内保存的マージ (Vranic k→2) で削減する。"""
    n_max: int = Field(100000, ge=1000)   # 種ごとの上限マクロ粒子数
    every: int = Field(100, ge=1)         # チェック間隔 [ステップ]
class PicSettings(...):
    merge: PicMerge | None = None         # None = マージ無効 (既定)
```

### es_sim/pic.py

- step ループ末尾 (注入・MCC の後) に `if merge and step % every == 0: _merge_species(...)`。
- 実装は種 (電子/イオン) それぞれに適用。numpy ベースで良い
  (毎ステップではないので速度は二の次。ソート+分割で O(N log N))。
- 診断: 累計マージ実行回数・削減粒子数を diag (coll_e 等と同様の optional カウンタ)
  か started/done のどこかに出す (最小限で良い: PicDiag に `merged?: int` 累計)。

### テスト (backend/tests/)

1. 保存性: 人工的な粒子集合 (1セル多数粒子) にマージを直接適用し、
   Σw / Σw·v (3成分) / Σw|v|² が相対誤差 1e-12 以下で保存、粒子数が減ること。
2. 上限制御: n_max を小さくした PIC 実行で、粒子数が n_max 近傍に維持されること
   (電離が起きる設定、または初期プラズマ大きめ+注入で)。
3. OFF時の不変性: merge=None の実行が従来とビット単位一致
   (乱数を引かないことの担保。既存テスト全パスでも傍証されるが、
   小ケースで merge=None vs 旧コードの結果一致を明示確認できればなお良い —
   実装上 OFF 経路に一切の変更が無いことのコードレビューでも可)。

`python -m pytest tests/ -q` 全件パス (現在 157)。

## frontend

- types.ts: PicMerge / PicSettings.merge。
- PicPanel の「PIC: 計算設定」末尾に:
  - Toggle 「粒子マージ」 (ON で merge を既定値 {n_max:100000, every:100} に、OFF で null)
  - ON のとき: 「上限マクロ粒子数 (種ごと)」「チェック間隔 [ステップ]」の CommitNumberInput
  - hint: 「電離で増え続けるマクロ粒子をセル内で保存的に統合します (重み・運動量・
    エネルギー保存)。IEDF等の分布に僅かな統計的影響があります。」
- 保存/読込は project.pic に自然に含まれる (確認のみ)。

## ベンチ (最終報告に含める)

電離が活発な合成ケースで merge OFF/ON (n_max 適当) の粒子数推移と ms/step を
数百ステップ比較し、上限維持と速度効果を示す。
