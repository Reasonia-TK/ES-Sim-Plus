# 132: v2 P7 — CAD v2 (計画)

計画書: `prompts/119-v2-rebuild-plan.md` (P7: CAD v2)。UI v2: `prompts/130-ui-v2-plan.md` (P6)。

## 目的

119 の P7 の項目: 線・円弧・円・ポリライン、辺/面の永続 ID で任意の辺に境界条件、スナップ (端点/中点/中心/交点/垂線/
接線/グリッド)、フィレット/面取り/オフセット/トリム、移動/回転/ミラー/尺度/配列、ブーリアン (和/差/積)、数値入力、
パラメータ式、レイヤ、DXF 入出力。完了基準は主要な操作の E2E テスト。

## 今の形 (P6 まで、バックエンドの調査の結果)

- **文書** (`Project.geometry`): ドメインは直線だけの多角形 (`domain.polygon`、反時計回りは説明だけで検査なし)、領域は
  多角形か円 (`polygon` / `shape`)。外周の辺は**番号**で指す (辺 k は頂点 k → k+1): 境界条件 `boundaries[].edges`、
  FN 放出 `particles.fn.edges`・`pic.fn.edges`、PIC の反射 `pic.reflect_edges`、DSMC `dsmc.boundaries[].edges` の 5 か所。
  番号の範囲の検査はばらばら (周期だけ検査、gmsh は無視、構造格子は `% 4`)。領域 ID の重複も検査していない。
- **v1 (gmsh、unstructured)**: 円は 1 周 24〜720 本の弦に分けてから OCC の直線で面を作り、`fragment` で重ねる。外周の辺と
  カーブの対応は「カーブの重心が辺の上にあるか」。境界のメッシュ辺にタグが無く、各エンジン (粒子の反射・周期、PIC、
  DSMC、流体、FN、構造格子) が「辺 k の上か」を**直線の判定**で求め直している (6 か所)。FN の導体の輪郭はメッシュと
  同じ多角形化を繰り返して照合している。
- **v2 (直交格子 + EB)**: 形状は多角形と真円 (解析的な交差)、ドメインは軸平行な矩形だけで、辺の条件は left/right/
  bottom/top に読み替える。GPU の PIC・DSMC のカーネルも 4 辺と「多角形・円の表」が前提。
- **UI**: 領域の作図 (折れ線・矩形・円)、選択・移動・頂点・辺の中点・半径、結合 (和、polygon-clipping、円・穴は不可)、
  グリッドへのスナップ。ドメインは矩形なら幅・高さ、それ以外は頂点表でだけ編集できる。

## 方針

1. **文書の形** (バックエンドのスキーマも同じ形にする):
   - **閉じた経路** = 頂点 `polygon` + 辺ごとの `bulges` (0 か省略 = 直線。円弧は bulge = tan(θ/4)、θ は中心角で正は
     反時計回り。DXF の LWPOLYLINE と同じ)。ドメイン・領域・穴で共通。円弧を含む経路は 2 頂点からでよい (半円 2 つで円)。
   - **穴**: 多角形の領域に `holes: [{polygon, bulges}]`。円の領域 (`shape`) は今までどおり。
   - **外周の辺の永続 ID**: `domain.edge_ids` (辺と同じ数、重複なし、`e1`, `e2`, …)。参照は今までどおり辺の**番号**のまま
     (バックエンドの約束を変えない) にし、UI が辺を分ける・消す・並べ替えるときに ID の系譜で 5 か所の番号を付け替える。
     辺を分けると両方に同じ条件が付き、消した辺の条件は外れる。ID が無い古い文書は読み込むときに振る。
   - **スケッチ** (領域でない線・円弧・円・ポリライン)・**レイヤ**・**パラメータ**は `project.cad`・`project.params`
     (ソルバーは使わない。スキーマには載せる)。
2. **バックエンドの円弧**: 検証の段階 (`Project` の検証) で円弧を弦に分け、エンジンには直線だけの多角形を渡す。
   - 分け方は円の多角形化と同じ密度 (1 周 ceil(2πr/h) 本を 24〜720 に、円弧は中心角の割合)。h は領域の局所メッシュ幅か
     全体のメッシュ幅、直交格子では最も細かい AMR の幅。
   - 外周の辺の番号の参照 (5 か所) は分けた弦の番号に展開し、電荷のラベルは元の辺の番号 (`edge{k}`) のままにする。
   - 理由: 外周の辺の判定が 6 か所に直線前提で分散し、GPU カーネルも多角形・円の表だけなので、ネイティブの円弧 (gmsh の
     円弧とメッシュ辺のタグ付け、カーネルの円弧) は全エンジンの改修になる。FEM は一次要素なので境界はいずれ弦になり、
     メッシュ幅の弦で精度は変わらない (今の円と同じ)。直交格子でも弦のたわみは最も細かいセルの数 % 以下。
   - 真円 (`shape`) は今までどおり (v1 は多角形化、v2 は解析的)。ジョブが返す文書は送った JSON のまま (円弧を保つ)。
3. **バックエンドの穴**: ネイティブに対応する。v1 は穴のある面 (gmsh のカーブループ)、構造格子と FN の輪郭は複数の輪、
   v2 の多角形は複数の輪 (偶奇規則なので内包・交差はそのまま)、GPU の表は「鍵穴」(穴を細い橋で外周につないだ 1 本の輪。
   橋は固体の中にあるので粒子の当たり判定は変わらない)。
4. **範囲外** (理由を付けて後の段へ):
   - 非矩形ドメインの直交格子 (EB) 対応: 4 辺前提の場・PIC・DSMC・流体・AMR とカーネルの改修になる。P7 では v1
     (unstructured) が任意の外周 (円弧を含む) を扱い、直交格子は矩形のまま (UI で知らせる)。
   - 領域の辺ごとの境界条件: 導体は 1 つの電位なので意味が決まらない (γ・粒子の境界の種類だけを辺ごとにする案はある)。
5. **幾何の計算は UI (TypeScript)** で行う (交点・スナップ・フィレット・オフセット・トリム・変換・ブーリアン)。
   ブーリアンは円弧を細かく分けて polygon-clipping で計算し、結果の頂点を元の曲線の交点に合わせ、同じ円弧の上の
   連続した点を円弧に戻す。
6. **DXF**: バックエンドに ezdxf を追加 (uv) して読み書きする案 (版・実体の種類・ブロック・単位に強い)。依存の追加なので
   P7g の前に確認する。
7. **パラメータ**: `params` (名前と式) と数値欄の式の束縛。文書には評価した数値も入れ (ソルバーはそのまま)、スイープで
   パラメータを変えたときはバックエンドが式を評価し直す (P7f)。

## P7d の記録 (2026-09-30)

  トリムで消える部分 (赤)、オフセット・延長の結果、フィレット・面取りする角を先に見せる。半径・長さ・距離は数字を
