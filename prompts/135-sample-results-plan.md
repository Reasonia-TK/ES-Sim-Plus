# 135: サンプルの保存された計算結果と GEC セルの PIC (計画)

依頼 (2026-10-03):

- 「GEC サンプルを PIC でも検証して」
- 「流体法も PIC もサンプルを開いたら保存されている計算結果を表示できるようにしたい」

決めたこと (2026-10-03):

- 結果は gzip の別ファイル (`examples/results/<サンプル>.json.gz`) にし、サンプルを開いたときだけ読む。RF の
  位相分解も含める (全部で約 10 MB)。作り直しはスクリプトで。
- 対象は流体・PIC のサンプル: GEC セル (流体 2D と PIC) と CCP デモ (PIC)。静電場・粒子軌道のサンプルは
  すぐ計算できるので付けない。
- GEC セルの PIC の設定は同じサンプル (`examples/gec_cell.json`) に足す (形と条件は共通)。
- サンプルを開いたら、保存された結果を自動で「読み込んだ実行」として並べ、最後のものを表示する。

## 今の形 (調査、2026-10-03)

- サンプルは UI がビルド時に `import.meta.glob("examples/*.json", {eager: true})` で取り込み (`io/examples.ts`)、
  メニュー「サンプル」の `openExample` (`io/documents.ts`) が文書にする。結果は扱わない。サンプルの JSON は
  起動時に全て読まれるので、結果を同じファイルに入れると起動が重くなる。
- 「結果付きで保存」(`results/bundle.ts`) は文書に `results: {version: 1, pic, pic1d, fluid1d, fluid2d, gas, tl,
  trace, solve, mesh}` を入れ、開くと `importResultsBundle` が「読み込んだ実行」として並べる (ビューア・グラフ・
  数値サマリが見られる。続きなどバックエンドの操作はできない)。サンプルの結果もこの形で持てば UI の読み込みは
  そのまま使える。
- 結果の束の大きさ (短い実行で測った。大きさは節点数と位相ビン数でほぼ決まる):

  | サンプル | JSON | gzip | 大きいもの |
  |---|---|---|---|
  | GEC 流体 2D (0.5 mm、3.7 万節点、16 ビン) | 19 MB | 3.5 MB | 位相分解 12.4 MB・時間平均の場 3.8 MB・メッシュ 2.9 MB |
  | GEC PIC (同じ格子、16 ビン) | 27 MB | 4.3 MB | 位相分解 20.7 MB (うち粒子のスナップショット) |
  | CCP デモ PIC (v1、275 節点、40 ビン) | 5.2 MB | 2.0 MB | 位相分解の粒子のスナップショット 4.7 MB |

- 長い実行では診断の履歴 (1 ステップ 1 行) が大きくなる (PIC で 800 ステップ/周期 × 数百周期)。
- GPU PIC の 1 周期の時間 (GEC の形、RTX 5070 Ti): 0.5 mm・100 万粒子で 2.2 秒、0.25 mm・400 万粒子で 6.8 秒。

## 設計

### 結果のファイル

- `examples/results/<サンプルのキー>.json.gz`: 結果の束 `{version: 1, meta, fluid2d?, pic?, ...}` (結果付きで
  保存と同じ形に、生成の記録 `meta` を足す)。`meta`: 生成日・es_sim のバージョン・計算した装置 (GPU 名)・
  種類ごとのステップ数と RF 周期数。UI は読み込んだ実行の名前に使う。
- 履歴は 2000 点ほどに間引く。阻止コンデンサの自己バイアスの履歴は「続き」をまたいで全部残す。
- 数値は有効数字 7 桁 (float32 相当) に丸めて JSON を小さくする。

### 作るスクリプト

- `backend/scripts/build_sample_results.py`: サンプルごとに、サンプルの設定でジョブと同じ組み立て
  (流体 2D: `make_fluid2d_simulation` と `Fluid2dRunner.result`、PIC: `make_pic_simulation` と
  `batch._build_results_bundle`) で走らせ、定常に近づくまで「続き」で延ばして、結果の束を書く。
- 延ばす長さはスクリプトの表に持つ (GEC 流体 2D: 約 100 周期、GEC PIC: 検証で決める、CCP デモ: サンプルのまま)。
- GPU の結果は実行ごとにわずかに違う (atomic) ので、作り直すと中身が変わる。エンジンを大きく変えたときに
  作り直す (README に手順)。

### UI

- `io/exampleResults.ts`: `import.meta.glob("examples/results/*.json.gz", {query: "?url", import: "default",
  eager: true})` で URL の表を作る (中身はビルドの資産になり、起動時には読まない)。
- `openExample`: 文書を開いたあと、結果のファイルがあれば fetch → `DecompressionStream("gzip")` → JSON →
  `importResultsBundle`。読み込み中・読み込んだ件数・失敗はメッセージに出す。
- 読み込んだ実行の名前は `meta` から「サンプルの結果 (100 周期)」のように。

### GEC セルの PIC (検証)

- サンプルの形と条件 (Ar 13.33 Pa・300 K、RF 電極 100 V・13.56 MHz、阻止コンデンサ 5 nF・初期バイアス −85 V、
  γ = 0.07) に PIC の設定を足す。断面積は eduPIC の Ar (Phelps)、初め 1e15 m⁻³・3 eV、dt = T/800。
- 格子: メッシュは文書に 1 つで流体と共通なので、流体と同じ 0.5 mm でよいか (λ_D ≈ 0.3〜0.4 mm、運動量保存型の
  PIC は h ≲ πλ_D で数値加熱が小さい) を、0.25 mm の計算と比べて決める。
- 比べるもの: 自己バイアス (Hargis ら 1994 の実測、流体の −85.2 V)、|V1|、電子密度・電子温度。

## SR-a の記録 (GEC の PIC と結果の束、2026-10-03〜04)

GEC の PIC の検証 (格子・粒子数、自己バイアス・密度、軸の近くの雑音) は prompts/134 の「GEC の PIC の検証」に書いた。
要点: 0.25 mm・400 万粒子の 600 周期で V_dc −76.5 V (比 0.77、流体 0.86・実測 0.67〜0.72)。0.5 mm でも 400 万粒子
なら 0.25 mm に近い (100 周期で 4% 以内、600 周期で密度 9%・Te 5% の差、V_dc 0.4%)。100 万粒子では軸の近くの雑音に
よる加熱で密度の山が育つ。

実装:

- `examples/gec_cell.json` に `pic`: 格子は流体と共通の 0.5 mm、400 万粒子、dt = T/800、既定 1.6 万ステップ
  (20 周期、時間平均は最後の 10 周期)、位相 16 ビン、SEE 2 eV。断面積は eduPIC の Ar (Phelps の解析式、PIC 1D の
  プリセットと同じ表を有効数字 6 桁で埋め込み。サンプルは 2 KB → 45 KB)。コレクタ 2 本 (RF 電極の上面・接地電極の
  下面の IEDF) と EEDF の領域 (中心、r < 20 mm・z 40.7〜44.7 mm)。
- `backend/scripts/build_sample_results.py`: サンプルの設定のまま走らせ、表 `PLANS` の周期数まで続きで延ばす。
  最後の区間に時間平均を入れる (平均の周期数も表に持つ)。履歴は 2000 点に間引き、自己バイアスの履歴は続きをまたいで
  全部残す。数値の桁: 既定 7 桁、時間平均の場・コレクタ 4 桁、位相分解 3 桁 (表示とシース端の積分には十分。時刻の
  ように差の小さい値を並べる履歴・回路・メッシュは 7 桁)。`--repack` で計算し直さずに桁だけ丸め直せる。
- `examples/results/gec_cell.json.gz` (7.6 MB): 流体 2D 100 周期 (GPU、V_dc −85.4 V) と PIC 600 周期 (最後の
  50 周期の平均、V_dc −76.2 V、IEDF の記録は 1 本 5 万個で打ち切り)。`ccp_demo.json.gz` (0.5 MB)。合わせて 8.1 MB。
  初めに全て 7 桁で書いたら GEC が 20.5 MB (JSON 74.5 MB、うち位相分解が流体 24 MB・PIC 38 MB) になったので、上の
  桁にした (JSON 62.7 MB)。
- README の GEC の行に PIC (保存された計算結果の節は SR-b)。
- → 2026-10-04 (prompts/136 RW-b): PIC を半径に比例した重み・200 万粒子で作り直した (`--only pic`、40 分、
  7.8 MB)。軸の近くの密度の山が無くなった。

確かめたこと:

- 作り直しの時間 (RTX 5070 Ti): 流体 100 周期は単独で約 19 秒/周期 (今回は PIC の検証と GPU を分け合ったので
  71 分)、PIC 600 周期は 57 分 (約 5.7 秒/周期)。サンプルの既定の PIC 20 周期は約 2.3 分。
- 中身: 流体の V_dc −85.4 V・|V1| 99.1 V、電子密度の最大 1.5×10¹⁵ m⁻³。PIC の V_dc −76.2 V・|V1| 99.0 V、
  電極の間の電子密度 2.9〜3.5×10¹⁵ m⁻³、中心の Te 3.1 eV。IEDF: RF 電極は最大 104 eV (時間平均のシースの電圧
  V_p − V_dc ≈ 99 V)・平均 23 eV (13 Pa の衝突の多いシース)、接地電極は最大 22 eV (プラズマ電位 22.6 V)・平均
  6.9 eV。中心の EEDF の T_eff 3.1 eV。
- ブラウザ (開発サーバー) で GEC サンプルを開くと 1 秒ほどで 2 件 (流体 2D・PIC) が並び、流体の時間平均の場が
  出る。PIC の実行のページに数値サマリ (V_dc −76.06 V・|V1| 99.03 V・比 −0.768)、グラフに RF 位相・自己バイアス・
  履歴・IEDF (コレクタの名前はサンプルの rf_electrode・ground_electrode)・EEDF・シース端のカードが出る (読み込み
  のあとのコンソールのエラーなし)。
- UI のテスト (GEC の結果の URL を足した)・型検査・ビルド。
