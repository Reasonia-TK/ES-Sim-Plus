# ES-Sim 仕様書

2D スケッチ CAD + 静電場・荷電粒子・低温プラズマのシミュレーションアプリケーション

- 版: 1.0 (アプリの 1.0.0 に合わせて改訂。初版 0.1 は 2026-07-21 の対話による仕様決定の結果)
- 日付: 2026-10-05
- 用途: 個人の研究・検討ツール。Windows のインストーラで配布する (v2 P8、prompts/133)
- 本書は機能と設計の要点をまとめる。各機能の経緯と検証の記録は `prompts/` (番号順)、検証の結果は
  `docs/VALIDATION.md`、DSMC のアルゴリズムは `docs/DSMC.md`、配布ビルドは `docs/PACKAGING.md`
- 節の番号はコードの docstring から参照されるので変えない。後から足した節は §9a のように枝番にする

## 1. 概要

2 次元の断面 (平面 x-y か軸対称 r-z) にジオメトリをスケッチし、そのまま解析にかけられるデスクトップ
アプリケーション。初版では「静電場 → 粒子軌道 → PIC」の 3 段階で広げる計画だった (§12)。今は次の解析を持つ。

| 解析 | 内容 | 節 |
|---|---|---|
| 静電場 | 電極・誘電体・空間電荷を置いて Poisson 方程式を解き、電位・電場・電極の電荷・容量・エネルギーを出す | §6・§7 |
| 粒子軌道追跡 | 解いた静電場 (固定場) と一様磁場の中の電子・イオンの軌道。FN 電界放出 | §8 |
| PIC-MCC (2D・1D) | 粒子の電荷を場に返す自己無撞着な時間発展。背景ガスとの衝突 (MCC)、RF 放電、自己バイアス | §9 |
| プラズマ流体 (1D・2D) | ドリフト拡散 + 電子エネルギー方程式。PIC と同じ条件で比べられる | §9a |
| DSMC | 定常ガス流れ。PIC の非一様な背景ガスにも使える | §9b |
| VHF 定在波 | 大面積 VHF CCP の非線形の径方向伝送線路モデル | §9c |
| Boltzmann 係数 | LXCat の断面積から流体の係数の表を作る | §9d |

PIC・流体の時間発展には、周期平均の量が落ち着いたかの判定 (収束の判定、§9e) が付く。

計算エンジンは 2 系統で、メッシュの方式 (`mesh.mode`、§5) で選ぶ。

- **v1**: 非構造三角形メッシュ (gmsh) か構造格子の上の P1-FEM。CPU (numpy/scipy + Numba)。2D の全ての解析が動く
- **v2**: 直交格子 + 埋め込み境界 (カットセル) と局所細分化 (AMR)。静電場・流体 2D は CPU/GPU、PIC・DSMC は
  NVIDIA の GPU (CuPy + 自前の CUDA カーネル)。prompts/119 で作り直した (§12)

1D の PIC・流体と VHF 定在波は、ジオメトリ・メッシュと関係しない専用のソルバー。PIC・流体は、パラメータ
スイープ (数値の欄やパラメータを掃引、prompts/79) とヘッドレスのバッチ実行 (`python -m es_sim.batch`、
prompts/78) で複数の条件をまとめて流せる。

## 2. 決定事項サマリ

初版 (2026-07-21) で対話により決め、その後の開発で広げた。括弧の中は初版からの変更。

| 論点 | 決定 |
|---|---|
| 実行形態 | デスクトップアプリ (Windows)。配布は NSIS のインストーラ (署名なし、prompts/133) |
| フロント | Tauri 2 + React + TypeScript。UI v2 (React 19 + Vite) で、2D ビューは WebGL2 + Canvas 2D の重ね描き、グラフは uPlot (初版は Canvas 2D 描画。prompts/130 で作り直した) |
| バックエンド | Python (FastAPI のローカルサーバー、サイドカープロセス)。配布版は PyInstaller の onedir |
| 解析範囲 | 静電場・粒子軌道・PIC-MCC (2D・1D)・プラズマ流体 (1D・2D)・DSMC・VHF 定在波・Boltzmann 係数 (初版は静電場 FEM → 粒子軌道 → PIC の 3 段階) |
| 数値解法 | v1 = FEM / 非構造三角形メッシュ (P1 要素)、v2 = 直交格子 + 埋め込み境界・幾何マルチグリッド・AMR (v2 は prompts/119 で追加) |
| 座標系 | 平面 2D (x-y、奥行き一様) と軸対称 (r-z、prompts/39・41)。1D は専用ソルバー (初版は平面 2D のみ) |
| CAD 規模 | シミュ用のスケッチ CAD: 線・ポリライン・矩形・円・円弧、スナップ、編集、ブーリアン、穴、パラメータ、レイヤ、DXF の読み書き (初版は簡易スケッチ。CAD v2、prompts/132) |
| 保存形式 | 独自 JSON のプロジェクトファイル (§10)。結果付きでも保存できる |
| 計算基盤 | numpy/scipy + Numba (CPU) と、v2 の GPU (CuPy + NVRTC で実行時にコンパイルする CUDA カーネル) (下記注記) |

### 計算基盤に関する注記(JAXからの変更)

当初 JAX(GPU)を候補としたが、JAX の GPU 実行は 2026年7月現在も Linux / WSL2 限定であり、
Windows ネイティブの CUDA 対応は未サポート(jax-ml/jax issue #32741、公式インストールガイド)。
「WSL2 は使いたくない」という制約と両立しないため、次の方針とした。

- **基盤**: numpy + scipy.sparse。v1 エンジンは全機能が CPU で完結する。粒子のホットループ (walk 探索・電荷堆積・
  プッシュ・MCC・DSMC の衝突) は Numba の JIT (`_numba_kernels.py`)。PIC は粒子のスレッド並列 (`pic.threads`)
- **GPU**: v2 エンジンで CuPy の配列と自前の CUDA カーネル (`es_sim/kernels/*.cu`) を使う。カーネルは NVRTC で
  実行時にコンパイルし、cuBLAS などは使わない (配布物には NVRTC だけを同梱、prompts/133)。同じ数式の Numba の
  カーネルも持ち、CPU/GPU の一致をテストする (`es_sim/device`)。NVIDIA の GPU だけ (AMD などの GPU は対象外)
- 初版の「`es_sim/backend.py` の `get_xp()` で v1 のホットループを numpy / cupy に切り替える」設計はやめた
  (v1 は Numba で速くし、GPU は v2 で作り直したため)。使っていなかった `es_sim/backend.py` と、計算に効いていなかった
  設定 `solver.backend` (UI の「行列計算」) は消した (GPU を使うかは `mesh.mode` と `es_sim/device` で決まる。
  v2 の静電場・流体 2D は GPU が使えれば GPU で解き (流体 2D は 1,000 節点以上)、環境変数 `ES_SIM_DEVICE=cpu` で
  CPU に固定できる。v2 の PIC・DSMC は GPU だけ)

FEM の疎行列直接法ソルブ(スパースLU)は CPU の方が実装・安定性ともに有利であり、
2Dの静電場(〜数十万要素)なら scipy で十分高速。v2 の静電場は反復法 (幾何マルチグリッド前処理 CG・AMG 前処理 CG)
なので GPU でも解ける。

## 3. アーキテクチャ

```
Tauri 2 アプリ (Rust シェルは薄く保つ: 同梱のバックエンドの起動と停止、ダイアログ・ファイルのプラグイン、§14)
 └─ WebView: UI v2 (React 19 + TypeScript、ui/src)
      ├─ モデルツリー・設定のページ (スキーマから作るフォーム)・CAD
      ├─ 2D ビュー (WebGL2 + Canvas 2D の重ね描き)・グラフ (uPlot)・実行ごとの結果
      └─ 下部パネル (進捗・ジョブ・メッセージ)・ステータスバー
             │ HTTP / WebSocket (127.0.0.1:8317。ポートは設定で変えられる)
             ▼
Python バックエンド (FastAPI + uvicorn、backend/es_sim)
 ├─ server.py・jobs/ : HTTP/WS の口とジョブ (同時実行・待ち行列・停止・続き)
 ├─ v1 エンジン      : meshing・fem・particles・pic・fluid2d・dsmc (CPU、numpy/scipy + Numba)
 ├─ v2 エンジン      : geom・eb・field・amr・gpic・gfluid・gdsmc (CPU/GPU、device・kernels)
 └─ 専用ソルバー     : pic1d・fluid1d・tl・boltz (boltzpmp)
```

- 開発中はフロント (`ui/` で `npm run tauri dev`。ブラウザだけなら `npm run dev`) とバックエンド (`uvicorn`) を
  別々に起動する
- 配布形態 (v2 P8、prompts/133・docs/PACKAGING.md): バックエンドを PyInstaller の onedir にまとめ、Tauri の
  リソースとして NSIS のインストーラに同梱する。アプリが起動時に立ち上げ、終了時に止める。GPU は CUDA の NVRTC
  だけを同梱して動かす (cuBLAS などは使わない)
- ポートの既定は 8317。UI で変えるとアプリの設定のファイル (AppConfig の `backend-port.txt`) に書き、同梱の
  バックエンドも次の起動からそれを使う
- 計算結果の大きい配列 (節点座標・要素・場) は JSON で送る。ジョブの進捗・フレームは間引いて最新だけ送る。
  バイナリ (ArrayBuffer) 化はまだしていない (§12)

## 4. CAD仕様

### 4.1 描画プリミティブ

- 線分、ポリライン(開/閉)、矩形、円、円弧
- 円は「中心+半径」のパラメトリック形状(`shape: {kind:"circle"}`)として保存し、
  **メッシュ生成時に** `n = clamp(ceil(2πr/h), 24, 720)`(h=その領域の特性長)で多角形化する。
  頂点間隔がメッシュサイズの下限になる問題を避けるため、固定分割の polygon 化はしない。
- 円弧 (CAD v2、prompts/132): ドメイン・領域の輪郭は頂点 `polygon` + 辺ごとの `bulges` (bulge = tan(θ/4)、
  0 は直線。DXF の LWPOLYLINE と同じ) で持ち、`Project` の検証の段階で円と同じ密度の弦に分けてソルバーへ渡す
  (外周の辺の番号の参照は分けた弦に展開し、電荷のラベルは元の辺の番号)。外周の辺には永続 ID `domain.edge_ids`
  を持ち、UI が辺を分ける・消すときに境界条件などの辺の番号を付け替える
- 穴 (P7e): 多角形の領域は `holes` (閉じた経路のリスト、円弧可) を持てる。穴の中はその領域ではない (下の領域・
  真空)。穴は外周の内側にあり、外周・ほかの穴と交わらず接せず、入れ子にしない (検証で断る)。v1 は穴のある面、
  構造格子・FN は全ての輪、v2 は輪で内包・交点を判定し、GPU の表は外周と穴を水平な橋でつないだ 1 本の輪

### 4.2 操作系

- グリッド表示・スナップ (端点・中点・中心・交点・垂線・接線・グリッド、印と名前、F3・Alt、P7c)
- パン(中ボタン/Space+ドラッグ)、ホイールズーム
- 選択(クリック/矩形)、移動、削除
- スケッチ (領域でない線・円弧・円・ポリライン、`project.cad.sketch`)、囲まれた所から領域 (線・円弧・領域・
  ドメインの辺で閉じた所をクリック)、閉じた形をドメインに (P7b、prompts/132)
- 数値入力: 作図中に打つと欄が開く (x, y ・ @dx, dy ・ @長さ<角度 ・ 長さ、単位と式、P7c)
- 編集: フィレット・面取り・オフセット・トリム・延長。変換: 移動・回転・ミラー・尺度 (コピーも)・配列 (矩形・円周) (P7d)
- ブーリアン: 領域の和・差・積 (円弧と穴を保つ。結果は元の領域の ID・値、分かれたら同じ値の新しい領域、相手は消すか
  残す)。囲まれた所から領域は面の中の島を穴にする。穴の頂点の表・穴を埋める (P7e)
- パラメータ: 名前付きの式 (単位付きの数・四則演算・関数、値は SI)。数値の欄にパラメータの名前を使った式を書くと
  その欄に束縛され、パラメータを変えると一緒に変わる (欄に数を打つと外れる)。スイープの対象にもなる (P7f)
- レイヤ: 領域とスケッチの表示・ロック・色 (表示だけ、計算には全ての領域を使う)。新しく描く形は今のレイヤへ (P7f)
- DXF: 読み込み (線・円弧・円・LWPOLYLINE・POLYLINE・楕円とスプラインは折れ線、ブロックは展開、単位は $INSUNITS か
  指定、レイヤを取り込む、閉じた形を領域にもできる) と書き出し (ドメイン・領域・穴・スケッチ、レイヤ・色)。解析と
  組み立てはバックエンド (ezdxf、`/v2/cad/dxf/import`・`/v2/cad/dxf/export`) (P7g)
- Undo/Redo: CAD に限らず全ての設定の変更を、プロジェクト全体の操作の履歴 (Immer のパッチ) で戻す・やり直す (P6a)

### 4.3 モデル構造

CADの目的は「閉領域と境界エッジに物理属性を付けること」。エンティティは次の3種。

- **domain**: 解析領域の外周(閉ポリゴン1つ。必須)
- **region**: 領域内の閉図形(電極・誘電体・空間電荷のいずれかの材料を割り当て)
- **boundary edge**: domain 外周や region 輪郭のエッジ列(境界条件を割り当て)

材料・境界条件:

| 種別 | パラメータ | v1 の FEM 上の扱い |
|---|---|---|
| 電極 (conductor) | 電位 V [V]。時間発展の計算では RF (`voltage_rf`、2 周波も)・CSV 波形・γ・阻止コンデンサ | 領域輪郭の節点に Dirichlet(領域内部はメッシュから除外) |
| 誘電体 (dielectric) | 比誘電率 εr、γ | 要素ごとの係数 ε = ε0·εr。PIC・流体では表面に吸収した電荷を蓄える |
| 空間電荷 (charge) | 電荷密度 ρ [C/m³] | 右辺ベクトルへ寄与 |
| 真空/空気 | εr = 1 | デフォルト材料 |
| 外周境界 | Dirichlet(V指定・RF・CSV 波形・γ・阻止コンデンサ) / Neumann(未指定) / **対称**(場はNeumann+粒子は鏡面反射) / **周期**(対辺ペアでDOF同一視+粒子ラップ) | エッジ単位で指定。周期は平行・同長の対辺2本を1エントリで指定 |

v2 は導体・誘電体の形を格子線との交点で表す埋め込み境界で扱う (§6.2)。軸対称では対称軸 (r = 0) の辺は自然境界で、
Dirichlet を付けられない。

### 4.4 単位系

SI(長さm、電位V、電荷C)。文書の中の長さは常に m。UI の長さの表示は mm か µm (アプリの設定)。数値の欄は
単位付きの入力 (13.56 MHz・0.5 ns・10 mTorr など) と式 (パラメータ、§4.2) を受け付ける。電荷・電流・容量の単位は
座標系で変わる (平面 2D は奥行き 1 m あたり、軸対称は全周)。

## 5. メッシュ生成

メッシュの方式は `mesh.mode` で選ぶ。

| mode | 内容 | エンジン |
|---|---|---|
| `unstructured` (既定) | gmsh の非構造三角形メッシュ | v1 |
| `structured` | 軸平行の矩形 domain の等間隔構造格子 (三角形 2 分割、高速、prompts/34) | v1 |
| `cartesian` | 直交格子 + 埋め込み境界 (EB)、局所細分化 (`mesh.amr`) | v2 (prompts/119・121) |

### 5.1 非構造三角形メッシュ (v1)

- gmsh(公式 Python API、**OCCカーネル + boolean fragment**)を使用
- 領域は domain と交差してよい(**外枠に重なる/はみ出す図形は domain にクリップ**される)。
  電極領域は穴として抜き、輪郭節点に Dirichlet を付与。誘電体・電荷領域は領域タグを保持
- 周期境界指定時は対辺のメッシュを `setPeriodic` で一致させ、スレーブ→マスター節点対応を保持
- メッシュサイズ: 全体特性長 + 領域単位 (`local_sizes`) + 任意の線分の近く (`local_edge_sizes`、prompts/90)。
  構造格子ではどちらも使わない
- 品質・要素数をメッシュプレビューで確認できること(/mesh を solve と分離する理由)

### 5.2 直交格子 + 埋め込み境界 (v2)

- domain は軸平行の矩形だけ。格子幅は `mesh.size` (マルチグリッドに合わせて最大 ~12% 細かくなる)
- 導体・誘電体の形 (多角形・円・穴) と格子線の交点を解析的に求めるカットセル。形に合わせたメッシュは作らない
  (/mesh は表示用に格子を三角形に分けて返す)
- 局所細分化 (`mesh.amr`、prompts/121): AMReX 型のブロック構造の階層 (blocking factor・proper nesting・隣接する
  葉セルのレベル差 ≤ 1)。レベル l の格子幅は size/2^l (l ≤ 6)。導体・誘電体の境界の近くと指定の矩形を細かくする。
  静電場は解に基づく適応細分化 (`adaptive`、prompts/122)、PIC は電子のデバイ長 (`pic_regrid_every`、prompts/123)、
  DSMC は平均自由行程 (`dsmc_regrid_every`、prompts/127) に合わせて実行中に格子を作り直せる (時間平均区間の前だけ)
- v2 へ移していない計算 (粒子軌道追跡) は、同じ矩形の構造格子 (形は階段近似) と v1 の FEM で解く

## 6. 静電場ソルバー

### 6.1 v1: P1-FEM

- 定式化: ∇·(ε∇V) = −ρ の弱形式、P1(線形三角形)要素。軸対称 (`coord` = `rz`・`rz_x0`) は 2πr を重みにした
  弱形式で、対称軸は自然境界
- 組み立て: 全要素一括のベクトル化組み立て(要素ループをnumpyで排除)→ scipy.sparse.coo → csr
- Dirichlet: 行削除方式(縮約)または大数法ではなく、対称性を保つ縮約方式を採用
- 求解: scipy.sparse.linalg.splu(直接法)。行列を保持し、右辺のみ変わる再解析(電位変更、PICの毎ステップ)は再分解なしで解く
- 導出量: E = −∇V(要素定数)→ 節点平均で滑らかな表示用フィールドも生成。電極ごとの誘起電荷 (残差法、prompts/71)、
  静電容量 (電極の電位がちょうど 2 水準で、空間電荷が無いとき)、蓄積エネルギー W = ½∫ε|E|²dΩ

### 6.2 v2: 埋め込み境界 + マルチグリッド (prompts/119 P2・P4)

- 節点の有限体積 (カットセル)。導体は Gibou の対称ゴーストフルイド法で 2 次精度、誘電体はカットセルの中の直列/並列
  合成
- 幾何マルチグリッド前処理 CG (AMReX の MLMG と同じく各レベルを幾何から再離散化)。CPU (Numba) / GPU (CuPy)。
  反復数は格子によらず 6〜7 回
- AMR: ぶら下がり節点を拘束で消した合成格子 (A_c = PᵀAP、対称正定値) を AMG 前処理 CG で解く (CPU は pyamg、GPU は
  pyamg の階層 + Chebyshev 平滑化を CUDA で)。粗細界面を含めて 2 次精度・電荷保存 (prompts/121・122)

### 6.3 検証ケース (自動テスト)

- v1:
  - 平行平板: V線形分布・E一様(解析解と比較、相対誤差 < 1e-10)
  - 同軸円筒(2D断面): V(r) の対数分布(メッシュ収束で確認、`backend/verification/coax_results.md`)
  - 誘電体境界: D法線連続の確認
- v2: 平行平板 (1e-10)、同軸で 2 次収束 (容量誤差 32² 1.4e-3 → 512² 9.4e-6)、誘電体、軸対称の同心球、周期・全
  Neumann、v1 の FEM との一致、CPU/GPU の一致。AMR は細分化なし・全域の細分化で一様格子と一致し、界面を含めて
  2 次収束

## 8. 粒子軌道追跡

- 前提: 静電場 (§6) を固定場として使う。一様磁場 `b_field` (平面 2D のみ、prompts/51) も加えられる
- 粒子種: 電荷 q・質量 m を指定(電子・陽子プリセット)。非相対論。面内の運動 (磁場があれば面外の速度、軸対称は
  周方向の速度も持つ)
- 積分器: リープフロッグ (kick-drift-kick)。磁場は Boris 回転。軸対称 (rz / rz_x0) は回転法 (局所座標の 3D の直線
  移動 → 子午面へ回転。角運動量を厳密に保存し、軸の近くでも発散しない。軸を通り抜けても r ≥ 0)。時間刻みは
  自動推定もできる
- 場の補間: 粒子位置を含む三角形を特定(walk探索+前回要素キャッシュ)→ 重心座標で E を補間(P1なら要素内一定)
- 粒子ソース: 点/線分エミッタ。エネルギー分布は単一エネルギー(mono)+角度広がり、
  または **Maxwell分布**(ドリフト+2D熱速度、温度 kT [eV]・乱数シード指定で再現可能)。
  FN 電界放出 (Murphy-Good 式 + Forbes 近似。電極の辺・導体の表面から電流に比例して放出し、総電流・粒子が担う
  電流を出す、prompts/46)
- 境界イベント: 電極・外周に到達したら吸収(衝突位置・エネルギー・**入射角**を記録)。対称境界は鏡面反射、
  周期境界は反対側へ
- 出力: 軌道のオーバーレイ表示、飛行時間・最終エネルギー・入射角。着地点の分布のヒストグラムは未実装 (§12)
- 実装: 全粒子を numpy で一括に進め、walk 探索は Numba。v2 (`cartesian`) の文書では同じ幅の構造格子と v1 の FEM で
  場を解いて追う (§5.2)

## 9. PIC (2D・1D)

3 つの実装を持つ。

| 実装 | 格子 | 実行 | 対応しない機能 |
|---|---|---|---|
| v1 FEM-PIC (`pic.py`) | 非構造三角形メッシュ・構造格子 | CPU (Numba、スレッド並列) | — |
| v2 GPU PIC (`gpic/`) | 直交格子 + 埋め込み境界、AMR | NVIDIA の GPU (CUDA Graph) | 注入・FN 放出・粒子マージ・DSMC 連成 |
| PIC 1D (`pic1d.py`) | 1D の一様格子 (1d3v) | CPU | DSMC 連成 (1D の機能は §9.4) |

### 9.1 2D の物理と機能

- 代表ターゲット: **低温プラズマ(CCP)**。電極・境界の電圧に RF 重畳
  `V(t) = V_dc + Σ A·sin(2πft + φ)`(`voltage_rf` フィールド、2 周波も、prompts/49)と CSV の波形
  (`voltage_waveform`、prompts/73) を指定可能
- **阻止コンデンサ (自己バイアス、prompts/134)**: 導体・Dirichlet 辺・1D の電極に `blocking_capacitor`
  (容量・初期バイアス) を付けると、電源と電極の間に直列のコンデンサを置き、電極の直流電位が放電に合わせて
  決まる (Vahedi & DiPeso 1997 の電位と回路の同時解、`circuit.py`)。容量の単位は座標系の電荷の単位
  (平面 2D は奥行き 1 m あたり F/m、軸対称は F、1D は面積あたり F/m²)。流体・PIC (1D・2D、v1・v2・AMR) の全てが
  使う。PIC は電極の電荷を Green の相反定理 (誘導電荷 −ψ̃·q) で求め、Poisson の前に電極の電位を決める (v2 の GPU
  PIC は回路もデバイスで進める)。静電場の計算 (/solve) は無視する
- **半径に比例した重み (軸対称、prompts/136)**: `pic.radial_weighting` (既定 true、v1・v2 PIC)。マクロ粒子の目標の
  重みを c·(r + r0) (r0 = v2 は基本格子の 1 セル、v1 は mesh.size) にして、セルあたりの粒子数を r によらずほぼ一定に
  する (重みが一定だと軸の近くの粒子が少なく、統計の雑音で軸の近くの電離・密度が過大になる)。毎ステップ、重さが目標の
  2 倍を越えた粒子を同じ位置・速度の粒子に分割し、1/2 を下回った粒子を同じセル (v1 は同じ要素) の軽い粒子と対にして
  1 個に併合する (速度は重みに比例した確率で一方のもの。電荷は厳密に、運動量・エネルギーは期待値で保存)。併合の位置は
  v2 が一方の粒子のもの、v1 は重み付き平均 (P1 の形状関数は要素の中で affine なので電荷堆積が変わらない)。v1 は粒子
  マージ (`pic.merge`) があると使わない (重みの調整が重なるため)
- 粒子種: 電子+イオン(質量 amu 指定、検証用にイオン固定オプション)の2種を常時管理
- **MCC衝突**: 背景中性ガス(一様圧力[Pa]・温度[K]指定)との null-collision 法。
  電子: 弾性(2m/M損失)・励起(閾値損失)・電離(新e+新イオン生成、余剰エネルギーは等分か乱数で分配)。
  イオン: 等方弾性・後方散乱(電荷交換。断面積の参照は実験室系か重心系)。断面積は **LXCat形式ファイルをインポート**
  (標準ブロック形式と、Phelpsイオンデータ等のタイプ行なし SPECIES/PROCESS 形式の両対応)し、
  パース済みテーブルをプロジェクトJSONへ埋め込む(`POST /lxcat/parse`)。非一様な背景ガス: DSMC の定常解を使う
  (`mcc.use_dsmc_gas`、局所密度比の null-collision と局所の温度・流速の Maxwell、v1 PIC のみ、prompts/54・83)
- **二次電子放出(SEE)**: 電極/Dirichlet辺・誘電体ごとに γ を指定(0=無効)。イオン衝突時に
  確率 γ で内向き法線方向に電子を放出(初期エネルギー指定可)。γモード放電の再現用
- 誘電体の表面電荷: 誘電体に吸収した粒子の電荷を表面に蓄える (prompts/25)
- 一様磁場 (平面 2D、Boris 回転、prompts/51)
- マクロ粒子: 重み付き超粒子。初期一様プラズマ、エミッタからの定常注入、FN 電界放出 (毎ステップの表面電界から
  I·dt 分の電子、端数は持ち越し)。粒子マージ (セルの中の保存的な併合で粒子数を抑える、prompts/77)、イオンの
  サブサイクル (prompts/50)
- 時間刻み: 既定は 0.1/ωpe (初期密度から)。開始時に ωpe·Δt とセル幅/デバイ長を確かめて警告する
- 診断: 全エネルギー(場+運動)と粒子数の履歴、位相空間プロット(x-vx等)、密度・温度などの場、時間平均
  (`avg_steps`)・RF 位相分解 (`phase_bins`)、IEDF/IADF のコレクタ (最大 8、prompts/30・36)、EEDF 領域 (最大 4、
  prompts/85)、シース評価線 (最大 4、prompts/98)、時間発展の収束の判定 (§9e)
- 実行制御: ジョブで進捗・中間フレームをフロントへストリーム、途中停止・続き (保持した状態から追加で実行)

### 9.2 v1 FEM-PIC

- 方式: FEM-PIC(非構造三角形メッシュ上のPIC)。構造格子PICより電荷堆積・粒子位置特定が難しい点は認識済み
- サイクル: ①電荷堆積(P1形状関数=重心座標の重みで節点へ散布)→ ②ポアソン求解(行列は固定、prefactorize済みLUで右辺のみ更新。Dirichlet 値は毎ステップ更新)→ ③E補間 → ④リープフロッグでプッシュ → ⑤境界処理・粒子注入
- 性能: walk 探索などは Numba、粒子をチャンクに分けたスレッド並列 (`pic.threads`。結果はスレッド数によらず
  ビット単位で同じ)

### 9.3 v2 GPU PIC (prompts/119 P3・P4)

- 1 ステップ (電荷堆積・Poisson・プッシュ・MCC・吸収の後処理 (表面電荷・SEE・コレクタ)・回路) を CUDA Graph で
  再生し、ホストと同期しない。v1 (8 スレッド) 比 18〜42 倍 (`backend/benchmarks/v2_bench.py`)
- AMR の合成格子の上でも動き、実行中にデバイ長に合わせて格子を作り直せる (§5.2)。粗細界面には粒子の自己力が残る
  (PIC の雑音や壁際の鏡像力と同程度、prompts/122)
- 誘電体の表面電荷は、衝突点のセルの 4 隅のうち誘電体の中の節点だけに双一次の重みを規格化し直して置く (表面の
  後ろ。v1 も進入した誘電体の要素の節点に置く)。気体側の節点にも置くと電位の極値が気体の中にでき、誘電体と導体の
  接合部で逆符号の粒子が表面の前に閉じ込められて育ち、GEC のサンプルが約 2300 RF 周期で暴走した (prompts/138)。
  誘電体が格子より薄く隅に誘電体の節点が無いセルだけは 4 隅に置く (一様格子は初期化で警告する)
- 対応しない機能 (注入・FN 放出・粒子マージ・DSMC 連成) はエラーで知らせる

### 9.4 PIC 1D (prompts/91〜100)

- 1d3v の一様格子 (三重対角の Poisson)。Turner ベンチマーク・eduPIC と同じ構成で、2D より桁違いに速い
- MCC (2D と同じ設定)・SEE、プリセット (eduPIC の Ar・Turner の He ケース 1)、RF 重畳 (2 周波も)・CSV 波形、
  FN 電界放出、阻止コンデンサ
- シース端 (Brinkmann) の位相分解と時系列の FFT、壁の IEDF

## 9a. プラズマ流体 (1D・2D)

- モデル: 電子・イオンの連続の式 (ドリフト拡散近似) + 電子エネルギー方程式 (局所平均エネルギー) + Poisson の
  自己無撞着系。流束は Scharfetter–Gummel (prompts/104〜106)
- 時間積分: 半陰的 (Poisson → E を固定 → その E の SG 係数で種ごとの連続の式とエネルギー方程式を後退オイラーで
  解く)。陽的な経路は検証用
- 1D (`fluid1d`): PIC 1D と同じ電極・格子の規約で、同じ条件・プリセットを直接比べられる
- 2D・軸対称 (`fluid2d`、prompts/111): v1 は三角形メッシュの EAFE (FEM-SG)。v2 は直交格子の双対セルの気体部分の
  有限体積 (固体は埋め込み境界、小セル併合、prompts/125)。v2 は輸送も GPU で解け (1,000 節点以上、prompts/126)、
  AMR の合成格子の上でも解ける (Voronoi 有限体積、prompts/128)
- 係数: 断面積の Maxwell 平均 (`fluid_coeffs.py`) か Boltzmann の表 (§9d)。イオンの移動度は修正 Frost 式
- 境界: 電極 (Dirichlet・RF・CSV 波形・γ) と阻止コンデンサ (自己バイアス)。外周の「なし (Neumann)」は反射壁。
  誘電体の表面は吸収した電荷を蓄えて浮遊電位へ緩和する (prompts/129)
- 診断: 時間平均 (`avg_steps`)・RF 位相分解 (`phase_bins`)、壁の IEDF (1D)、時間発展の収束の判定 (§9e)

## 9b. DSMC (定常ガス流れ)

- NTC 法 + VHS 分子モデル (Bird の標準形)、prompts/54。アルゴリズムと検証は `docs/DSMC.md`
- セル: v1 は三角形メッシュの要素、v2 は直交格子のセル (GPU、prompts/124)。v2 は AMR の葉セルも使え、平均自由行程に
  合わせて格子を作り直せる (prompts/127)
- 境界: 拡散反射壁 (壁温。指定の無い辺の既定)・鏡面 (対称)・圧力リザーバの流入/流出・流量指定の流入 (sccm)・
  真空排気。辺の一部 (線分) にも付けられる (prompts/55)。軸対称にも対応 (prompts/56)
- 定常後の時間平均で n・T・u・p を出す。PIC の背景ガスに使える (§9.1)

## 9c. VHF 定在波

- 円板電極の大面積 VHF CCP の非線形の径方向伝送線路モデル (Lieberman ら 2002・Chabert ら 2004、prompts/101・102)。
  中心給電・軸対称の径方向 1D
- シースの非線形容量が作る高調波と、波長が短くなった定在波 (実効波長・吸収電力の一様性・給電電力)
- ジオメトリ・メッシュと関係しない専用のソルバー (`tl`)。PIC 1D の結果から電子密度とシース厚を取り込める

## 9d. Boltzmann 係数

- boltzpmp (伝播演算子法、Rust、prompts/117・118) で LXCat の断面積から E/N ごとの EEDF・電子移動度・速度定数を
  求め、平均エネルギーで引く表 (`BoltzTable`) にして流体 (1D・2D) の係数に使う (局所平均エネルギー近似)。
  超弾性衝突とガスの熱運動による加熱も既定で入る (BOLSIG+ と同じ物理)
- 断面積は `es_sim/xs` (prompts/120): boltzpmp のパーサーの上位互換 (DATABASE・複数ガス・ROTATION・`<->` の統計
  重み・3 列目の運動量移行・PARAM./COLUMNS の単位・Phelps のイオン形式)、EFFECTIVE→ELASTIC の厳密変換、混合ガス
- ジョブ (`boltz`) が表を作り、文書へ書き戻す

## 9e. 時間発展の収束の判定 (prompts/137)

PIC (1D・2D、v1・v2・AMR) と流体 (1D・2D、v1・v2 の CPU/GPU・AMR) の時間発展で、周期平均の量が落ち着いたかを
判定する (`es_sim/convergence.py`)。設定は各スタディの `convergence` (`ConvergenceSettings`、§10)。

- 標本: 判定の周期 (RF の最低周波数の周期 × `rf_periods`。RF も CSV 波形も無ければ `steps` ステップ、既定は
  frame_every の 10 倍) ごとの周期平均。境は絶対時刻で決める (阻止コンデンサの集計と同じ。続きの実行でもつながる)。
  量は φ と n_e (気体の節点を約 32×32 (1D は 64) の粗いブロックに体積で平均し、体積で重み付けした L2 で比べる)、
  電子・イオンの総数、阻止コンデンサの電極ごとの自己バイアス V_dc (尺度は |V1|)。流体は毎ステップ、PIC (1D・2D)
  は 1 周期に 64 回ほど足し込む (v2 の GPU PIC はデバイスで足し、周期の境の同期点で判定する)
- 判定: 量ごとに、三階差分から周期ごとの雑音の分散を見積もり、窓の平均どうしの比較の雑音の幅が閾値の半分以下に
  なる窓 W (最大 `max_window`) を選ぶ。変化 D は直近 W 周期と前の W 周期の平均の相対差 (雑音の分を引く)。残りの
  変化 R は、3 つの窓の差の比 q (誤差の上限 q⁺ を使う) から等比の外挿 D'·q⁺/(1 − q⁺) で見積もり、今の傾きで
  これまでの周期の数の 10 倍走ったときの変化で上限を切る (減っていると言えないときはその上限)。全ての量で
  D ≤ `tol` かつ R ≤ `tol` (既定は流体 0.001・PIC 0.01) の周期が `hold` 回 (既定 3) 続いたら収束とし、最初の 1 回の
  周期・時刻・ステップを記録する。判定は 7 周期 (と窓の 3 倍) から。PIC と雑音のある量は 3 × `max_window` 周期から
- PIC の量の残りの変化 (CV-d): 粒子の雑音と周期をまたぐ揺れがあるので、上の窓の走査ではなく長い履歴の回帰で
  見積もる。周期平均を等しい長さのビン (最大 64 個、あふれたら隣どうしを合わせる) にまとめて持ち、これまでの
  周期の後ろ半分に直線を当てて傾きを 1 回だけ検定する (スカラーは 3σ 相当の t 分布の点、場はブロックの雑音を
  まとめた χ² の点 (自由度は残差から見た実効的なブロックの数)。分散は二次式を当てた残差から見積もり、残差の
  隣どうしの相関 ρ で (1 + ρ)/(1 − ρ) 倍する)。有意なら、区間の前半と後半の傾きの比 (上限 3σ) で減り方を見分け、
  減っていれば時定数 × 終わりの傾き (上限 3σ、decay)、減っていると言えなければ傾きが後ろ半分の長さだけ続いた
  ときの変化 (span。流体の 10 倍の外挿は、総数のゆっくりした揺れを傾きとして外挿して定常でも不合格にした)。
  分解能 (検定で見つけられる最小の傾きで後ろ半分の長さだけ走ったときの変化) が `tol` を越えるうちは合格にしない
- 状態: 判定中 (warming)・揺れが大きく比べられない (noisy、窓が `max_window` で足りない。流体でも走り始めの速い
  変化でなることがある)・未収束 (fail)・合格 (pass)・判定中 (resolving、PIC で変化は閾値以下だが遅い傾きを見分ける
  にはまだ周期が足りない)
- 止める (`stop`): 収束したステップから平均区間 (`avg_steps`、未指定なら判定の周期 10 個分) を取って止める
  (n_steps は上限になる。ジョブの進捗の総ステップ数も早めた終わりまでにする)。時間平均・位相分解・コレクタなどの
  区間は収束の次のステップから取り直す (区間がもう始まっていたら今の終わりまで走る)。続きの実行は判定の状態を
  引き継ぎ、前に収束していれば止めない
- 結果とフレーム: 結果の `convergence` に閾値・判定の周期、周期ごとの時刻・ステップ・窓・状態、量ごとの D・R・
  雑音の幅・R の見積もり方 (`r_kind`: none = 有意な変化なし、decay = 減り方から外挿、trend = 傾きの 10 倍の延長 (流体)、span = 後ろ半分の長さの延長 (PIC))・分解能
  (`res`、PIC)、収束した周期・時刻・ステップ、止めたか。フレームには今の状態 (いちばん遠い量・分解能がいちばん粗い
  量)。スイープのケースの要約にも載る
- UI: 各スタディの設定の「収束の判定」、実行のページの数値サマリ (実行中は今の状態、PIC は分解能も)、グラフ (量ごとの
  max(D, R) の推移を対数で、閾値の破線・PIC の分解能の点線・収束の縦線・CSV)、スイープのケースの一覧の「収束」の列
- 限界: 収束としたときに見逃しうる遅い傾きは、PIC では分解能の範囲 (調べた後ろ半分の長さで閾値の分ほどしか
  変わらない傾き。それより長く続けば、見えた所で不合格に戻る)。雑音が閾値と同じくらいの量は、分解能が届くまで
  250〜350 周期ほどかかる (閾値を上げると早まる)。
  PIC で途中で急に止まった変化は、傾きを見る後ろ半分から抜けるまで (止まった周期の約 2 倍まで) 不合格のまま。
  流体の窓の走査は、時定数がこれまでの長さの 10 倍を越える緩和を見分けられない

## 13. 非機能要件

- 性能: 初版の目標は「静電場 10 万要素の求解 + 表示更新を数秒以内 (CPU)」。v2 の GPU は 1024² の静電場を 81 ms、
  PIC は v1 (8 スレッド) の 18〜42 倍、DSMC は 35 倍、流体 2D の輸送は v2 の CPU の 8〜28 倍 (prompts/119)。表示は
  24.5 万三角形の描き直しが 11 ms (P6c)
- すべての解析機能はGUIなしでも Python から呼べること(`es_sim` をライブラリとして import 可能に保つ。パラメータ
  スイープ用)。ヘッドレスのバッチ実行 (`python -m es_sim.batch`、配布版は `es-sim-backend.exe batch`) もある
- 自動テスト: ソルバーは解析解・基準解 (Turner・eduPIC など)・v1 との比較を必須とする。CI (GitHub Actions の
  `ci.yml`) で pytest、UI の型検査・Vitest・ビルド、E2E (Playwright) を走らせる。CI のランナーには GPU が無いので、
  GPU のテストは GPU のある PC で走らせる (CUDA が無いと飛ばす)
- 配布版の確認: `scripts/verify_installer.ps1` (インストール → 同梱のバックエンドの自己テスト → UI から計算 →
  アンインストール)。リリースは `v*` タグで `release.yml` がインストーラを作る
- クラッシュ耐性: 解析はバックエンドプロセス内で完結し、失敗してもUIは巻き込まれない (ジョブの失敗は UI に出す)

## 14. 既知のリスクと対応

| リスク | 対応 |
|---|---|
| FEM-PIC の実装難度(粒子位置特定・電荷堆積) | フェーズ2で walk探索・重心座標補間を先に固め、PICで再利用 (済み) |
| Windows での GPU 制約 | v1 は numpy/scipy + Numba で全機能が CPU で完結する。v2 の静電場・流体 2D は GPU が無ければ CPU で解く。v2 の PIC・DSMC は NVIDIA の GPU (CUDA 13 の対象、Turing 以降・ドライバ R580 以降) だけなので、GPU の無い PC ではメッシュの方式を v1 にする |
| GPU の計算の非決定性 | 原子操作の順で実行ごとにわずかに違う (保存された結果は作り直すと変わる)。テストは許容差で比べ、CPU/GPU の一致テストを持つ |
